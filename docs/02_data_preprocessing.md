## 1. Dataset — VinBigData Chest X-ray

### 1.1 Overview

**Dataset:** VinBigData CXR (Chest X-ray 14+1 Abnormalities)
**Source:** Kaggle / VinBigData competition
**Format:** DICOM files with CSV annotations

**Relevant statistics (after filtering):**
- Classes used: **Cardiomegaly** (enlarged cardiac silhouette, CTR > 0.5) and **Normal** (no radiologist-annotated finding)
- VinBigData has 14 pathology classes; only cardiomegaly and normal are used in the current training split
- Bounding box annotations from multiple radiologists per image (union used; see §4.2)
- Images are 2-channel (single grayscale), various native resolutions (mostly 1200–3000px wide)

**CSV path:** `/datasets/mmolefe/vinbigdata/cache_npy/train_filtered.csv`
**Cache directory:** `/datasets/mmolefe/vinbigdata/cache_npy/`

### 1.2 Class split

The `train_filtered.csv` was generated by `scripts/regen_filtered_csv.py`. It filters to Cardiomegaly and Normal images with:
- Exclusion of images appearing in multiple disease categories (comorbidities)
- Exclusion of Cardiomegaly images without any bbox annotation (no spatial supervision possible)
- Exclusion of Normal images with any co-annotation

The resulting dataset contains only "clean" examples for disentanglement training — each image is unambiguously one class.

## 2. Preprocessing Pipeline

All preprocessing lives in [datasets/VinBigData.py](../datasets/VinBigData.py). The net result is a `float32 (1, H, W)` tensor in `[-1, 1]`, polarity-corrected, windowed, and size-standardized.

### Step 1 — MONOCHROME1 Polarity Fix

**Problem:** Some VinBigData DICOMs use `MONOCHROME1` photometric interpretation, where **bones are dark and air is bright** — the inverse of clinical convention. Training with mixed polarities causes the model to see anatomically inconsistent images.

**Detection:** Read the `PhotometricInterpretation` DICOM tag from the header.

**Fix:**
```python
if photometric == 'MONOCHROME1':
    arr = arr.max() - arr
```

Applied before any windowing, so all images share the `bones-bright / air-dark` profile regardless of scanner origin.

**Where:** [`datasets/VinBigData.py:338`](../datasets/VinBigData.py#L338) (live load) and [`scripts/cache_dicoms.py:49`](../scripts/cache_dicoms.py#L49) (cache generation)

**Why this matters:** Without the polarity fix, the model sees half the dataset with inverted contrast. The encoder must learn two contradictory feature representations of the same anatomy, wasting capacity and producing unstable latent structure.

---

### Step 2 — VOI-LUT Windowing

**Problem:** Raw DICOM pixel values span 0–4095 (12-bit). Different scanners use different dynamic ranges. Direct normalization without windowing would produce inconsistent contrast.

**Fix:**
1. Read `WindowCenter` and `WindowWidth` from DICOM metadata (preferred path)
2. If absent or out of range: use 1st–99th percentile of pixel values (robust fallback)

```python
lower = wc - ww / 2
upper = wc + ww / 2
windowed = np.clip(pixel_array, lower, upper)
windowed = (windowed - lower) / (upper - lower + 1e-8)  # → [0, 1]
```

**Why not just normalize by max?** Hard-coded CT defaults (`wc=40 / ww=400`) would clip all X-ray pixels to white — X-rays have much higher window values than CT. The percentile fallback is critical.

**Where:** [`datasets/VinBigData.py:344-356`](../datasets/VinBigData.py#L344)

---

### Step 3 — Blank / Corrupt Image Rejection

Images with `std < 0.02` after windowing are rejected as blank or uniform. DICOMs that fail to parse are dropped. Both are replaced via retry sampling from the same class pool (up to 10 retries per sample).

```python
if windowed.std() < 0.02:
    return None  # triggers retry
```

**Where:** [`datasets/VinBigData.py:359`](../datasets/VinBigData.py#L359)

---

### Step 4 — Resize

Images are resized to `img_size × img_size` (training uses **256×256**; full resolution is 512×512 but not used due to memory):

- **Live DICOM path:** PIL `BICUBIC` interpolation — fast, good for downsampling
- **Cache generation:** PIL `LANCZOS` interpolation — higher quality for the offline step

**Where:** [`datasets/VinBigData.py:377`](../datasets/VinBigData.py#L377) (live), [`scripts/cache_dicoms.py:59`](../scripts/cache_dicoms.py#L59) (cache)

---

### Step 5 — Normalization to `[-1, 1]`

```python
x = np.asarray(img, dtype=np.float32) / 255.0   # [0, 1]
x = x * 2.0 - 1.0                                # [-1, 1]
x = x[None, ...]                                  # (1, H, W) channel-first
```

This is the expected input range for the VAE encoder (sigmoid output in decoder reconstructs to `[0, 1]`, which maps back to `[-1, 1]` target via the loss).

**Where:** [`datasets/VinBigData.py:380-382`](../datasets/VinBigData.py#L380)

## 3. Cache System

### 3.1 Why caching matters

Loading and windowing DICOMs at training time (the "live DICOM path") adds ~100ms per sample from disk. At batch_size=6 with 8 workers, this creates a data loading bottleneck. The cache system pre-applies Steps 1–4 and stores as uint16 numpy arrays.

### 3.2 Cache format

**Storage:** `uint16` numpy arrays, one `.npy` file per image

```python
# During cache generation (scripts/cache_dicoms.py):
arr = arr / arr.max() * 65535.0
np.save(dest, arr.astype(np.uint16))   # lossless 16-bit encoding of [0,1]

# At load time (datasets/VinBigData.py):
arr = np.load(path).astype(np.float32) / 65535.0   # recover [0,1]
# then → _preprocess_image() → [-1,1]
```

**Why uint16 not float32?** 2× disk space savings (2 bytes vs 4 bytes per pixel). At 256×256 uint16: 128KB per image vs 256KB float32. For 15,000 images: ~1.9GB vs ~3.8GB.

**Lossless?** The uint16 range (0–65535) provides 16-bit precision. After normalization to [0,1] and round-trip via multiply-by-65535 / divide-by-65535, the maximum quantisation error is 1/65535 ≈ 1.5×10⁻⁵ — below float32 precision at this range.

### 3.3 Loading modes

| Mode | `--use_cache` | Source | I/O cost | Use case |
|------|--------------|--------|----------|----------|
| Live DICOM | `False` | `.dicom` files, VOI-LUT on the fly | High (~100ms/sample) | First run, diagnostics |
| Cache NPY | `True` | Pre-cached `.npy` uint16 arrays | Low (~5ms/sample) | All training runs |

**Always use `--use_cache` for training.**

### 3.4 Generating the cache

```bash
python scripts/cache_dicoms.py \
    --input_dir /datasets/mmolefe/vinbigdata/raw_dicoms/ \
    --output_dir /datasets/mmolefe/vinbigdata/cache_npy/ \
    --img_size 256 \
    --num_workers 16
```

The script also generates `train_filtered.csv` with pre-normalised bounding box coordinates (see §4.2).

## 4. Bounding Box Annotations

### 4.1 Why bounding boxes matter for SepVAE

The bounding boxes are not used for supervised classification — they are used to give the disease head a spatial prior from epoch 1 via BboxCrossAttnHead. Without bbox guidance, the disease head would need ~30–50 epochs to learn where to look for the cardiac region from scratch. With it, the disease head concentrates on the cardiac silhouette from the first batch.

### 4.2 Annotation format and processing

**Raw format:** `(image_id, class_name, x_min, y_min, x_max, y_max)` in pixel coordinates, multiple radiologist annotations per image.

**Union bbox:** When multiple radiologists annotate the same pathology, we take the union (min/max over all annotations):
```python
x0 = min(all_annotations['x_min'])
y0 = min(all_annotations['y_min'])
x1 = max(all_annotations['x_max'])
y1 = max(all_annotations['y_max'])
```

**Normalization to [0, 1]:** Divide by original DICOM dimensions (before resizing):
```python
bbox_norm = [x0 / W_orig, y0 / H_orig, x1 / W_orig, y1 / H_orig]
```

Stored in `train_filtered.csv` as four columns: `x_min_norm, y_min_norm, x_max_norm, y_max_norm`.

**Where:** [`datasets/VinBigData.py:261-264`](../datasets/VinBigData.py#L261) and [`scripts/cache_dicoms.py:155-163`](../scripts/cache_dicoms.py#L155)

### 4.3 How bounding boxes flow to the model

**In dataset:** Each batch element returns `bbox_tensor_4 ∈ [0,1]⁴` alongside the image tensor.

**In BboxCrossAttnHead:** The bbox defines a 2D Gaussian spatial prior:
- Centre: `(cx, cy) = ((x0+x1)/2, (y0+y1)/2)`
- σ = `(x1-x0) / 4` (quarter-width; prior drops to ~14% at the bbox boundary)
- The prior is projected to the 16×16 latent grid via bilinear projection
- Used to compute Q_bbox — the initial query driving cross-attention

**Normal images:** `has_bbox = 0`, so Normal images use the learned fallback query Q_learned. The Gaussian prior is never applied to Normal images. The `stop_gradient` fix ensures Normal image gradients do not corrupt the key projection.

### 4.4 bbox_dropout

`bbox_dropout_prob = 0.3` — 30% of training steps randomly drop the bbox input for Cardiomegaly images (replace with `has_bbox = 0`, using Q_learned). This forces the model to be robust to missing annotations at inference time and prevents over-reliance on bbox coordinates that may be imprecise.

## 5. Dataset Class — VinBigDataset

### 5.1 Triplet sampling

The dataset returns triplets `(anchor, positive, negative)` for contrastive training:

| Position | Class | Usage |
|----------|-------|-------|
| anchor | sampled from batch pool | primary image |
| positive | same class as anchor | contrastive pull |
| negative | opposite class | contrastive push |

All three go through the full preprocessing pipeline independently. The triplet is collated into `(B×3, 1, H, W)` batches by the dataloader.

### 5.2 Deterministic sampling

`--deterministic_data` flag: when set, uses a fixed-seed sampler that ensures the same batch ordering across runs. This allows reproducible training and meaningful checkpoint comparisons.

### 5.3 Batch composition at training time

Each batch of size B contains:
- B/2 Cardiomegaly images (approximately — actual ratio depends on class distribution in the filtered CSV)
- B/2 Normal images
- Triplet structure: each image also draws its positive and negative pair

At `batch_size=6` (D3 default), the effective training batch is:
- 18 images processed by the encoder (6 triplets × 3)
- 6 images decoded (anchor only, after z sampling)

## 6. Known Data Issues

### 6.1 MONOCHROME1 scans in production cache

Early caches were generated without the polarity fix. Any run before the fix was added to `cache_dicoms.py` (around early March 2026) may have a subset of inverted images in the cache. The current `train_filtered.csv` includes a flag column `polarity_fixed` indicating which images were reprocessed.

**Mitigation:** Always regenerate the cache with the current script version. Runs using the old cache showed instability in FactorDisc training — the polarity inversion created inconsistent anatomy features that confused the MI discriminator.

### 6.2 Missing bboxes for some cardiomegaly images

Some Cardiomegaly images in the original VinBigData CSV have no radiologist bbox (only a class label). These are excluded from `train_filtered.csv` by the filtering script (since BboxCrossAttnHead requires a bbox for the Gaussian prior). Their exclusion slightly reduces the training set size but ensures consistent spatial supervision.

### 6.3 Resolution variability in native DICOMs

Native DICOM resolutions vary from ~1200×1000 to ~3000×3000 pixels. After resize to 256×256, the effective pixel spacing varies across scanners. This is not corrected for (doing so would require DICOM metadata parsing per scanner) — it is accepted as a source of variance that the model must be robust to.
